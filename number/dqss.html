02核心成果：伤害结算体系的完整展开

这是本项目的核心资产。它看起来只是一个公式，但真正的工作量在公式下面——每一个系数都要找到它的全部来源，并判定叠加规则。

伤害 = (攻击 × 基础倍率 + 固定值伤害) × (1.871 × 角色倍率修正值)
        × 条件收益系数 × 属性克制系数 × 打击类型系数
        ÷ (防御 × 贯穿 / 300 + 1)

攻击(防御) = 面板攻击(防御) × 攻击(防御)力修正

条件收益系数 = 己方增伤 × 目标减伤

系数来源穷举（这才是"自己拆的"证据）

修正项来源清单叠加规则
攻击力修正状态类 4 种 + 被动类 11 项不同效果类型累加；相同类型取最大值
防御力修正状态类 3 种 + 被动类 6 项各项累加；相同效果类型取最大值
己方增伤10 项技能 + 9 件神器 + 1 套装 + 2 BOSS 被动各项累加
目标减伤2 项技能 + 5 件神器 + 隐身 BUFF取最高值，不叠乘（单项格式：1-a%）
贯穿9 项技能 + 1 件神器各项叠乘（单项格式：1-a%）
倍率修正技能升级 / 专属装备 / 转职技能树各项累加

分水岭

只有公式 = 抄的；有"系数穷举 + 叠加规则分层" = 自己拆的。因为前者任何人复制粘贴就能得到，后者必须把每一个增益、每一件装备、每一个被动逐条翻一遍，并判断它是取最大值还是叠乘——这正是数值策划日常在做的事。

03判定链与行动顺序

打击类型：三级瀑布，而非并行判定

闪避 → 暴击 → 强击 → 普通。关键在于强击只在暴击判定失败之后才判定，且强击发生率只受属性克制影响（克制 80%、非克制 30%，基线 30%）。这两条决定了该作"高暴击角色为什么能同时压低强击收益"。

效果命中：二级瀑布，且带截断区间

闪避 → 命中，命中率取值区间上限为 85%。更值得记的是它反推出的对抗式设计：命中与闪避是技能与神器提供的属性，而不是角色自身属性——这一条是理解"为什么辅助角色在该作中偏强"的钥匙。

行动顺序：速度与速攻值双轨制

  • 双轨：速度（静态数值）与速攻值（百分比进度）分离，进度条上限 300。
  • 四级仲裁：速攻值高 → 进攻方优先 → 速度值高 → 位置号低。
  • 回合内 8 步流程：DOT 结算早于强控判定；额外行动后速攻值重置为 +999%。
  • 强控优先级：睡眠 = 眩晕 > 挑衅 > 沉默。

04一个被低估的素材：战斗 AI 行为优先级

这是全项目最稀缺的一部分，也是我最想展示的部分。玩家攻略几乎从不覆盖战斗 AI 的目标选择与技能触发顺序，因为它只在自动战斗中体现，且需要逐角色观测才能得到。

维度规则
默认技能顺序S3 → S2 → S1
目标优先级BOSS → 属性克制 → HP% 最低 → 随机
位置修正前排自带 40% 受击率
角色覆盖项逐角色列出自定义 AI 例外规则（共 383 行）

为什么这一项价值高：目标优先级直接决定自动战斗的实际输出效率，也直接影响玩家对角色强度的判断。能把 383 行例外规则整理成可判定的规则集，说明拆解没有停在"看表面数值"这一层。

05可复用的工具

拆解过程本身也应该被工具化，否则每换一个项目就要重做一遍解析。

拆解报告模板 固定七段：研究对象与边界 → 观测数据 → 反推假设 → 解方程 → 交叉验证 → 结论与区间 → 我的改进建议。后续每一期拆解都套它，保证产出结构一致。
证据链四段自评表 逆向拆解 / 数值建模 / 验证闭环 / 工具化，逐段打星并强制填写缺口。

06下一步

按性价比排序，而不是按重要性排序——先做能立刻闭环的。

  1. 合规边界处理与表述清理素材剔除、图片重绘、口语化表述改写为设计语言。
  2. 关键常数反推日志为 1.871、300、85% 这三个反推常数各写一段"观测 → 假设 → 解方程 → 交叉验证"。
  3. 倍率修正值回归分析用 599 行数据做拟合，输出拟合函数与残差分布。验证闭环的开篇案例。
  4. 伤害计算器（Excel）输入层 / 系数层 / 结算层 / 校验层四段式，全表无硬编码结果值，校验区能主动报出系数越界与分母为零。
  5. 模拟与敏感性脚本（Python）蒙特卡洛输出战斗时长分布，边界扫描输出暴击率 0→100% 与贯穿 0→100% 的敏感性曲线。
  6. 三张验证实验卡假设 → 实验设计 → 观测记录 → 结论。即使结论是推翻原假设也照写。
